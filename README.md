> 函数式编程的核心则在于组合（像乐高一样），为了组合，组合的函数最好是纯函数，处理数据时保证不可变性。

## 特征
- 拥抱纯函数，隔离副作用
- 函数是“一等公民”：可以被当做变量一样用（参数、返回值、被赋值），因为函数本质上是一个可执行对象
- 避免对状态的改变（不可变值）

## 纯函数
- 对于相同的输入，总是会得到相同的输出
- 无副作用

### 为什么非“纯”不可？
因为纯函数是高度灵活的函数，它的计算逻辑在任何上下文里都是成立的。不纯的话，一旦脱离特定上下文，就会失去预期效果，可复用性差，迁移的难度也会增大。
实践纯函数的目的并不是消灭副作用，而是**将计算逻辑与副作用做合理的解耦**，提升编码质量和执行效率。

## 不可变数据：函数纯度的安全帽
- **`immutable.js`**：采用字典树（Trie）数据结构，只更改发生变化属性的引用，共享未变化部分的内存。
- **`immer.js`**：利用 ES6 `Proxy` 代理，在可变（mutative）的写法中自动创建数据的拷贝并返回新的不可变对象，开发体验极佳。

## 柯里化 (Currying)
把接受多个参数的函数变换成一系列接受单一参数（或部分参数）的函数。
它的核心意义在于**参数的“分期付款”**：可以通过先传递部分参数来生成一个专用的、等待剩余参数的新函数。这使得函数变得更容易被复用，也是实现 `compose`（函数组合）和 Pointfree 风格的基石。

## 高阶函数
指的就是接收函数作为入参，或者将函数作为出参返回的函数。

## 函数组合思想 (Compose)
把待组合的函数放进一个数组（或管道）里，数据像流水一样从一端流向另一端。
- 实现原理：利用数组的 `reduce`（或者 `reduceRight`）方法，将多个独立的功能函数串联成一个工作流。
- **Pointfree 风格**：在组合的过程中完全不提到底层的数据（参数），只关注函数的组合。

## 容器与 Functor (函子)
为了在组合的高级流水线中安全、优雅地处理包含副作用、错误或空值的数据，我们引入了“容器”的概念，把数据包裹起来。

**Functor (函子)** 就是实现了 `map` 方法并遵守特定规则的容器类型。
它的意义在于：提供了一种**在不离开容器的情况下，操作容器内部值**的能力（通过向 `map` 传递一个改变值的纯函数）。结合柯里化的 `map` 辅助函数（即把 `functor.map(f)` 包装成 `map(f)(functor)`），函子可以完美融入 `compose` 流水线。

### 常见的 Functor
1. **Maybe Functor**
   用来处理 `null` 和 `undefined`。它可以安全地穿过整条错误的数据管道而不会引发抛错。
   - 内部包含为空的检查（`isNothing`），一旦为空，它立刻返回包含 `null` 的新 Maybe，跳过后续所有函数的实际执行。

2. **Either Functor (Left / Right)**
   用作优雅的 `try/catch` 替代品，专治错误处理。
   - **`Right`**：代表计算成功，它的 `map` 会正常应用函数并继续传递下去。
   - **`Left`**：代表计算失败（保存了错误信息），它的 `map` 什么都不会做，直接把错误原样透传。
   - 最后通常配合一个 **`either(f, g)`** 辅助函数，在数据管道的最末端进行“拆包”，决定走错误处理逻辑还是成功处理逻辑。

3. **IO Functor**
   用来处理副作用。
   - 它包在里面的不是具体的值，而是**一个等待执行的函数（计算过程）**。
   - 当调用 `IO.map` 时，它不会执行内部的函数，而是利用 `compose` 把传进来的计算挂载到原有的计划上。
   - 以此实现**延迟执行（Lazy Evaluation）**：把所有的业务逻辑变成一个干干净净的“计划表”，直到程序的最外层边界手动“扣动扳机”（调用 `.__value()`），最终的副作用才合并爆发。
